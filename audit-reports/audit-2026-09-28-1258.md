# Codebase Audit Report — Bluesheet

## Date: 2026-09-28 12:58 BST
## Scope: Handoff project, with emphasis on geometry, numerical contracts, caching, slicing and print handoff

## Coverage

This bundle has no `.git`; `COMMITS.txt`, the design documents, vault notes and `sdd-workspace/progress.md` supplied recent-change context. No earlier audit report or plan exists here, so this is the baseline.
- **Deep-read:** `js/kernel/{mesh,validate,pack,joint,provenance,trace,comic,bambu,bambu-profile}.js`, `js/gen/creature.js`, relevant `js/ui/{build,build-core,library,slice}.js`, `js/app.js`, `server.py`, `server/{slicer,library,plate,bambu,printer}.py`, relevant tests and build tools.
- **Skimmed:** Other 21 generator modules, registry, WebGL viewer, analysis UI, server modules outside the print path, and creature acceptance gates. Those received entry-point/contract and automated-test coverage, not line-by-line review.
- **Skipped:** Deployed scratch-it Worker and origin Linux installation, hardware print measurement, OrcaSlicer execution without its local profiles, and inaccessible external production telemetry. No claim of exhaustive source review follows from the word “complete” in the request.
- **Tools run:** 23/23 registry sync; static build (4.34 MB, five server-only controls hidden); Python `test_made.py` 57/57 and `security_probe.py` 62/62; `test_server.py` 227/230, with three failures from absent Orca profile files; `ruff check` six low-impact lint errors; mesh snapshot 156/157 identical; full Node runner 56/59 suites and 7,954/7,954 reported assertions. No npm package or third-party Python dependency manifest exists, so dependency scanners have no project dependency set; mypy, eslint and vulture are not installed. A Python unittest discovery command ran zero tests because this project uses direct scripts, then the scripts were run directly.

## Executive Summary

The core geometry conventions are well documented and the cross-generator conformance tests are unusually strong. Registry and static-publication checks pass. A 1,072-case numerical probe of `fitToBed` found no pose round-trip errors. The live jaw and content-hash paths have two confirmed high-impact failures: valid jaw settings can let the mandible escape, and a changed image pixel can reuse a previous build. The LAN print endpoint also relies on network trust rather than authentication; this is an explicit design choice, but any client on that network can issue its own confirmation token.

The release evidence is incomplete. The Dragon preset's mesh fingerprint differs from the stored baseline by 218 triangles, while the resulting mesh still passes watertightness analysis. On this Mac, Orca profiles and the AppImage are absent, so slicing integration cannot be confirmed. Browser catalogue imports failed intermittently on early runs and succeeded later. These are gates to resolve before treating the recent changes as print-ready, not proof that a printed object or origin installation is broken.

## Findings by Category

### Geometry and mathematics

**F01 — High — Jaw captivity check is missing for small valid heads.** `jawGeometry()` sets barrel radius to `0.28 × head radius` at [`js/gen/creature.js:1569`](../js/gen/creature.js#L1569). The code's own geometric derivation requires `Rk > 2.4 × clearance` for the opening chord to stay narrower than the barrel at [line 1593](../js/gen/creature.js#L1593). [`validate()` at line 2174](../js/gen/creature.js#L2174) checks the spine ball, but has no equivalent jaw test. Reproduction: `bodyR=4.5`, `profile=flat`, `head=dragon`, `jaw=true`, `clearance=0.6`, `limbPairs=0` returns no validation errors. Its barrel diameter is 2.646 mm against a 2.720 mm mouth chord; translating the built mandible along that opening yields zero intersection with the skull. The same result occurs at body radius 4.75 mm. **Recommendation:** Apply the jaw inequality in `validate()` for jaw-capable heads or resize the barrel/socket to remain captive across the declared parameter range. Pin the boundary with a geometric pull test, not only a formula assertion. A separate `0.7999999999999998 < 0.8` comparison at the body-wall boundary creates an erroneous warning; use a small numerical tolerance there.

**F02 — Medium — Dragon preset mesh differs from the saved fingerprint.** `node tools/mesh-snapshot.mjs check` reports 156 of 157 matches and `creature/preset:Dragon` changed: 53,934 to 53,716 triangles, 26,995 to 26,886 vertices, hash `ade490b4c7f34886` to `f2abde2e4c9bf97b`; volume and bounding box are unchanged. The stored record is [`tests/fixtures/mesh-snapshot.json:1652`](../tests/fixtures/mesh-snapshot.json#L1652). A fresh direct Dragon build has zero boundary and non-manifold edges. This is a reproducible release-baseline mismatch, not evidence by itself of a bad solid. **Recommendation:** Determine which recent triangulation change caused it, inspect the intended shape and joint clearance, then intentionally refresh the fingerprint only if the change is accepted. The snapshot check must be green for a release.

**F03 — Low — Nested creature guidance cites the open-seam measurement.** Preset construction selects `fit('nested')` for nested seams at [`js/gen/creature.js:1955`](../js/gen/creature.js#L1955), but the resulting analysis note always appends `fitNote('free')` at [line 2246](../js/gen/creature.js#L2246). A Dragon preset therefore reports 0.30 mm clearance followed by the 0.35 mm open-joint measurement. **Recommendation:** Select the note by `p.seams`, and assert the exact nested message in a cheap test.

### Caching, data integrity and print handoff

**F04 — High — The image-field cache key skips most pixels.** [`js/kernel/provenance.js:57-65`](../js/kernel/provenance.js#L57) hashes every 64th value of a 512 × 512 field. [`js/ui/build.js:29`](../js/ui/build.js#L29) uses that canonical result as the mesh cache key. Two 512 × 512 arrays differing only at index 1 have identical `canonicalise()` and `paramHash()` outputs, so editing a comic, lithophane or terrain input can display/export the previous geometry. **Recommendation:** Hash every field element in a stable representation, and add a regression that changes a formerly unsampled pixel, confirms a new key, and confirms a rebuilt mesh. A 32-bit identifier still has normal collision risk; sparse sampling is the deterministic defect here.

**F05 — Medium — A cached slice can retain the prior object's name.** [`server/slicer.py:423-431`](../server/slicer.py#L423) hashes STL bytes, placement and settings but omits `obj['name']`; cached metadata at [lines 458-464](../server/slicer.py#L458) returns names assembled at [line 566](../server/slicer.py#L566). Reproduction: `job_id([{'data': b'abc', 'name': 'one'}], s) == job_id([{'data': b'abc', 'name': 'two'}], s)` is true. **Recommendation:** Include each object's effective name in the job ID, or keep artifact caching geometry-only while building response metadata from the current request. Test a rename against an existing cache entry.

**F06 — Medium — Bambu export ignores the selected material.** [`js/ui/build-core.js:209`](../js/ui/build-core.js#L209) carries the chosen material for slicing, but the Bambu handoff at [line 251](../js/ui/build-core.js#L251) passes no settings. [`exportBambuProject()` at `js/kernel/bambu.js:138`](../js/kernel/bambu.js#L138) consequently uses the single stored A1-mini/SUNLU PLA+ project profile documented at [`js/kernel/bambu-profile.js:1-9`](../js/kernel/bambu-profile.js#L1). The imported-object path at [`js/app.js:563`](../js/app.js#L563) does likewise. A user choosing PETG or TPU can open a PLA-configured project. **Recommendation:** Either export a separately verified profile for each supported material, or label this action as a fixed PLA Bambu project and require explicit material review in Bambu Studio. Do not generate an unverified profile by string replacement.

**F07 — Medium — The design-library cap silently deletes user data.** A save at [`server/library.py:108-121`](../server/library.py#L108) writes the new entry, then `_enforce_cap()` unlinks every entry past 500. This has not fired in the sampled three-entry library, but it will silently erase older designs as use grows. **Recommendation:** Reject the 501st save with a visible quota message, or archive/export old entries with an explicit user choice. Preserve existing files on write failure.

### Security and operations

**F08 — High — LAN clients can invoke mutating routes and print initiation without identity.** [`server.py:765`](../server.py#L765) listens on all interfaces. POST and DELETE use same-origin checks at [lines 249-280](../server.py#L249), which protect a browser against cross-site requests but allow clients with no Origin header. The two-step `/api/print` flow at [lines 574-596](../server.py#L574) issues its confirmation token to that same caller and accepts caller-supplied `bedClear: true`. The security probe confirmed the CSRF controls work; it does not prove LAN authorization. On a shared or compromised LAN, a client can change library data or start a job if the printer is available. **Recommendation:** Bind to loopback by default or require authentication on mutating LAN endpoints; protect the printer-start operation with a separate secret or trusted authenticated session. If a trusted-LAN deployment is intentional, state that boundary and enforce it with host firewall rules.

**F09 — Medium — Static publication removes any existing destination directory.** [`tools/build-static.mjs:21-29`](../tools/build-static.mjs#L21) prevents deleting the source tree but calls `rmSync(OUT, {recursive:true, force:true})` for every other path. A mistyped destination can erase unrelated user files, including vault data. **Recommendation:** Require a marker left by a prior Bluesheet build before replacing an existing directory, build into a sibling temporary directory, and swap only after validation. Provide an explicit one-time adoption path for the existing public destination.

**F10 — Medium — Local slicing tests are tied to origin-machine Orca profiles.** [`server/slicer.py:45-55`](../server/slicer.py#L45) defaults to `~/.local/share/orca-profiles` and rejects missing presets at [lines 259-263](../server/slicer.py#L259). On this Mac, `tests/test_server.py` gives 227/230: `test_slicer_settings`, `test_placement`, and the busy-slicer case fail because the profiles are missing (the latter gets 422 before it can assert 503). The UI suite also explicitly fails its slicing check when `/api/health` says Orca is absent at [`tests/ui.test.mjs:573-628`](../tests/ui.test.mjs#L573). **Recommendation:** Keep real-machine slicing as an integration gate, but make pure settings/placement and queue tests use temporary minimal profile fixtures. Record missing Orca as an explicit skipped integration check rather than a misleading code failure. Run real slicing on the target machine before release.

**F12 — Medium — Catalogue imports intermittently fail in real Chrome.** [`js/gen/index.js:53-68`](../js/gen/index.js#L53) imports all 23 generator modules at once and records any rejected fetch as a permanently missing catalogue entry for that page. With the local server running, fresh browser runs loaded 21, then 10, then 5 of 23 modules; rejected reasons named `Failed to fetch dynamically imported module`. Direct `curl` of a failed file returned HTTP 200. Three later fresh boots loaded 23/23 and the full browser suite passed 85/85. A separate trial with server connection backlog 128 also passed, but later success on the unmodified server means the backlog is only a hypothesis, not an established cause. **Recommendation:** Capture request-failure details in the browser gate, reproduce under controlled concurrent load, and then either bound import concurrency, raise the server backlog, or retry transient fetches once. Preserve the useful behaviour where a genuinely broken module leaves the rest of the catalogue usable.

### Maintainability

**F11 — Low — Recent species commentary and lint have drifted.** [`js/gen/creature.js:1863-1867`](../js/gen/creature.js#L1863) says Capybara is 4 × 28, while the executable preset is 3 × 26; the latest `sdd-workspace/progress.md` ruling supersedes the comment. `ruff check server.py server tests/*.py` flags six small Python issues (two unused imports, four ambiguous `l` identifiers). **Recommendation:** Correct the comment and progress header to the current ruling; clean the six lint errors and add a lightweight lint check to the portable test path. Neither lint result is evidence of a runtime bug.

**F13 — Low — The UI search test races its debounce and thumbnail work.** [`tests/ui.test.mjs:321-329`](../tests/ui.test.mjs#L321) types “box”, sleeps a fixed 260 ms and immediately counts cards. [`js/ui/catalogue.js:61`](../js/ui/catalogue.js#L61) debounces the input by 90 ms while thumbnails are rendered in the same page. Twice the test saw the field contain “box” but still counted 23 cards; a fresh browser allowed 2 seconds and correctly showed two cards. **Recommendation:** Poll for the filtered card count (with a bounded timeout) rather than relying on a fixed sleep, and keep a separate check that the input event was delivered.

## Checks and limits

- **Passed:** Registry 23/23; static build; `test_made.py` 57/57; `security_probe.py` 62/62; Node runner's 7,954 reported assertions; standalone browser 85/85 and plate 18/18 with the server up; jaw and hash reproductions on actual module paths; 1,072 fitting cases round-tripped; direct Dragon mesh analysis found a watertight solid.
- **Failed or blocked:** Snapshot 1/157 changed; server integration 3/230 fails because Orca profiles are absent; Python lint six findings; UI 107/109 with a timing-sensitive search check and an explicit no-Orca failure. The initial full Node run had 56/59 suites because browser/plate/UI were started without the required server; it cannot be called an all-green run. Intermittent catalogue fetch failures need investigation.
- **Unmeasured:** Real printed joint clearance, hardware printer authorization, deployed public site, and Orca-generated 3mf on this machine. The code's published fit measurements should not be replaced by inference from mesh triangles.

## Recommended Priority Order

1. F08: Secure the LAN printer and write routes before use on any network containing untrusted devices; the existing token does not authenticate a caller.
2. F01: Make jaw captivity a validated geometric contract before printing small/high-clearance variants.
3. F04: Fix the field checksum so changed inputs cannot silently reuse old meshes.
4. F06 and F05: Align material selection and slice names with the exported/cached artifacts.
5. F02, F10 and F12: Resolve the Dragon snapshot, run a genuine Orca integration check on the target machine, and investigate intermittent browser imports before release.
6. F09, F07, F03, F11 and F13: Remove avoidable data-loss paths and misleading guidance, then tighten portable checks.
